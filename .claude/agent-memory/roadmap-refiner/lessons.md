
## frontend-uplift-2026q2 (2026-05-20)
- **Brief extraction pattern:** The brief was a 300-line final-report from a prior `/frontend-uplift` research pass, not a short conversational summary. When the brief is itself a structured artifact with ranked candidates, the HMW reframe must collapse the catalog into a single outcome statement — resist listing candidates in the HMW clause. The beneficiary is the solo developer, not an abstract "user", because this extension is unpublished.
- **Assumption classification — MUST threshold:** The `motion` library initial-chunk gate and `lucide-react` tree-shaking verification are both `[MUST]` because getting them wrong invalidates the entire bundle-budget claim that justifies shipping UPL-1/UPL-8 as "safe". The 200 KB ceiling is a hard constraint from CLAUDE.md, not a soft preference.
- **Assumption classification — SHOULD vs MIGHT:** Single-source candidates (15/26 at ±50% confidence) re-ranking is a `[MIGHT]` not a `[SHOULD]` — re-ranking only affects sequencing, not the validity of the foundation sprint. Contrast this with UPL-2 Path a feasibility, which is `[SHOULD]` because failure forces milestone substitution.
- **Prior art discovery:** `plans/sprint-backlog-redesign-roadmap.md` is the closest prior roadmap (same UI surface, prior milestones m1–m3 exist) but touches different concerns (backlog UI, not tokens/motion). Use `grep -l "motion\|theme\|CSS\|token"` on plans/ to detect thematic overlap, not just file names.
- **Won't list discipline:** For a visual-modernization roadmap, 5 Won't items were natural: CWS publish, server components, React 19 / UPL-26, Inter font (lowest RICE MAJOR), and design-system scaffolding. The 60% rule from anti-patterns.md was not a gate issue here (REFINE has no Must-cap; that's SEQUENCE) — but naming the deferred items explicitly prevents scope creep at decomposition time.
