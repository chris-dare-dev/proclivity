# Recurring anti-patterns observed by milestone-adversary-critic

Append-only log. Each entry: `<pattern-name> | <how to detect> | <how to mitigate>`.

---

**Selector-fan-out via shared markers (className or tag+attribute)** | Any new CSS rule whose selector relies on a tag or className that ALSO appears on non-target DOM nodes inside the scoped subtree. Detected by reading the parent's full JSX (not just the children the synthesis lists) and enumerating every direct child + every node carrying the keyed marker. Observed in m5 (`.todo-list` matched card-fallback-list and ArchivedSprintRow `<ul>`s) and m4 (`.content > div` matched `.section-empty`). | Prefer a positive semantic anchor (`[role="tabpanel"]`, explicit `data-tabpanel`) over `:not()` chains. When the implementer copies a selector verbatim from research synthesis, the critic must re-derive the match-set against the real JSX tree, not the synthesis's listed targets.

**Commit-subject ≤50-char drift (off-by-2)** | Subject after `feat(scope): ` prefix measured by `printf '%s' "..." | wc -c` exceeds 50 by 1–3 chars. Eyeball estimates consistently undercount. Observed in m4 (52 chars) and at least one prior milestone per m5 lesson. | Implementer should run the printf-wc-c check as a pre-commit local step. Repo would benefit from a commit-msg hook enforcing this; until then, every adversary critic should measure programmatically and flag HIGH on overrun.

**Synthesis-prescribed classifications copied verbatim by implementer** | Research synthesis enumerates "covered/uncovered" buckets or "matches/excludes" selector targets; implementer trusts the list as ground truth without re-verifying. Observed in m3 (theme.css "fully uncovered" was wrong on 2/9 files) and m5 (`.card-fallback-list` exclusion claim was illusory) and m4 (`.section-empty` fan-out unflagged in synthesis selector). | Critic's standing rule: synthesis classifications are hypotheses. Independently re-derive via `grep` / file-read before judging fit. The synthesis writer and the implementer never close the loop on bucketing accuracy — only the critic does.

**Scope `motion` used but not in CLAUDE.md scopes list** | Commit subject `feat(motion): ...` lands when CLAUDE.md "Scopes in active use" list (gantt, sprint, reminders, mesh, storage, build, a11y, skill, roadmap, docs, tune, style, perf, refactor, fix, feat) does not include `motion`. Observed m5-M1 (deferred) and m4-M1 (deferred) and m7-M1 (third recurrence). | Either add `motion` to the CLAUDE.md scopes list (justified by the frontend-uplift roadmap's 9 motion-themed UPL candidates) or instruct implementers to use `style` going forward. Decision should not be deferred a third time — m7 was the third deferral; bundle the CLAUDE.md edit with the next motion milestone's rectifier pass.

**Animated-exit window leaves focus-trap + event handlers wired** | When AnimatePresence (or any animated-exit mechanism) keeps the panel DOM alive for ~150-200 ms after `open=false`, the `useFocusTrap` (or equivalent) hook + its `onKeyDown` handler remain wired. The rAF-style focus restoration runs once (~16 ms) but does NOT prevent subsequent Tab presses from re-pulling focus into the closing panel. Observed m7-H1. | Implementation pattern: `<m.div {...(!open ? { inert: '' } : {})} onKeyDown={(e) => { if (!open) return; trapFocus(e); }}>`. Defensive `inert` attribute removes the panel from the focus tree synchronously while the visual fade-out completes. Regression test: open modal → press Escape → press Tab within 100 ms → assert `document.activeElement` is outside the panel.

**Motion imports added to base component eagerly consumed by N top-level surfaces** | New `import { m, AnimatePresence } from "motion/react"` added to a Modal/Drawer/Sheet base that is consumed (NOT lazily) by ≥3 top-level surfaces will tree-shake INTO the initial chunk, NOT the lazy modal/drawer children — the chunk graph is determined by where the importer lands, not by where the conditional render fires. Observed m7 (initial chunk +15.9 kB vs synthesis prediction +0 kB). | Phase 1 check: enumerate the eager consumers of any base component before predicting where new imports land. If the base has ≥3 eager consumers, predict the imports land in the initial chunk; only "animated sibling extracted into a separately-imported file" guarantees lazy placement.

**Scope `deps` used but not in CLAUDE.md scopes list** | Commit subject `feat(deps): ...` lands when CLAUDE.md "Scopes in active use" list does not include `deps`. Observed m10-M (deferred), m11-M (deferred), m8-M1 (third recurrence, this lesson). The `deps` scope appears when a milestone is primarily a dependency-addition (sonner+auto-animate, react-hotkeys-hook, cmdk) and neither `build` nor `feat` cleanly fit the semantic. | Add `deps` to the CLAUDE.md scopes list — the dependency-addition cadence is consistent (m10/m11/m8 are three of the last four milestones). Bundle the CLAUDE.md amend with the next rect pass. Past deferral by m8.

**Synthesis AC numerical drift from source brief's projection** | A synthesis writes a numerical AC (e.g. "≤ N kB raw") that paraphrases the source brief's projection but tightens or loosens it without noting the change. The implementer hits the brief's projection (not the AC) and reports AC met against the global ceiling, not the synthesis AC. The inconsistency is silent unless the critic re-reads the brief's projection table directly. Observed m8-M2 (synthesis AC3 said 280 kB raw; brief-2 §Bundle delta projected 301.78 kB raw; actual 301.62 kB raw — matches brief, fails AC verbatim). | Phase 1 check: "For each numerical AC, locate the source brief's exact projection and verify the AC value is consistent (target ≥ projection for ceilings, target ≤ projection for floors)." Critic should re-read the source brief's numerical tables, not just the synthesis paraphrase.
