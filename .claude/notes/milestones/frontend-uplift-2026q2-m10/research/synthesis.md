## 1. TL;DR for the implementer

Two stories. Scope tighter than the roadmap spec suggested.

**Critical scope correction from research:** there is exactly **ONE** `document.addEventListener("keydown", ...)` in the entire `src/` tree — `ChatPanel.tsx:48–55` (Escape closes chat panel). All other "keydown" matches are JSX `onKeyDown=` handlers properly scoped to form inputs, widget internals, or modal backdrops. **Do NOT migrate JSX `onKeyDown` handlers.** Specifically, `Modal.tsx:88-97` Escape handling MUST stay JSX-bound — its `e.stopPropagation()` is load-bearing for nested-modal stacking (ConfirmDialog inside SettingsModal). Migrating to `useHotkeys("escape")` would break the modal-stack semantics.

**Architecture:**
- `useHotkeys("mod+slash", ...)` in App.tsx — single binding, library's `mod` resolves to Cmd on Mac, Ctrl on Win/Linux (verified in brief-2 §3.3). With `preventDefault: true` to suppress `/` insertion in focused inputs.
- `src/lib/shortcuts.ts` — Option 1 (flat const array with `keys`, `label`, `category` fields). Brief-2 §3.6 prefers Option 1 for m10's tiny shortcut count; defer Option 3 (auto-registry context) to a future milestone.
- `src/components/help/KeyboardHelpOverlay.tsx` — lazy-loaded modal that reuses the m7 Modal scaffold (gets AnimatePresence scale-in + focus-trap + Escape-to-close for free). Renders shortcuts grouped by category in a two-column layout. Uses `isMacOS()` from `react-hotkeys-hook` (exported from `index.ts`) to render ⌘ vs Ctrl in the key labels.
- `src/components/help/KeyboardHelpOverlay.css` — minimal styles for the shortcut-list two-column layout (most styling reuses `modal-*` classes from Modal.css).

**Files touched:** 6 unique paths (counting package.json + package-lock.json + ChatPanel.tsx + shortcuts.ts + KeyboardHelpOverlay.tsx + KeyboardHelpOverlay.css + App.tsx = 7). This crosses the ≤5-files inline threshold → **delegated path** via a `milestone-implementer` agent in a worktree.

**Expected chunk delta:** +~2.9 KB gz from react-hotkeys-hook + ~0.5 KB for shortcuts.ts in the initial chunk. KeyboardHelpOverlay + its CSS are lazy-loaded — no initial-chunk impact. Target initial chunk ≤ 260 kB (baseline 251.52 kB post-m7).

## 3. Architecture decisions made during synthesis

### 3.1 ONE migration target, not "every ad-hoc handler"

Per brief-1 §3.1 + brief-2 §3.7 + §5: only `ChatPanel.tsx:48-55` matches `document.addEventListener("keydown", ...)`. The roadmap brief's wording "replace all ad-hoc `document.addEventListener('keydown')` calls" maps to exactly this one call. JSX `onKeyDown=` handlers are NOT in scope.

### 3.2 Modal.tsx Escape handler stays JSX

Brief-1 §3.2 + brief-2 §3.7: migrating Modal.tsx to `useHotkeys("escape")` would break nested-modal stacking. The existing `e.stopPropagation()` in `handleKeyDown` is the load-bearing mechanism that prevents a nested ConfirmDialog's Escape from also closing the parent SettingsModal. `useHotkeys` has no modal-stack awareness — both would fire on the same keydown.

### 3.3 `mod+slash` is the canonical cross-platform binding

Brief-2 §3.3: `react-hotkeys-hook` v5 implements `mod` natively in `validators.ts` — resolves to `metaKey` on macOS (Cmd) and `ctrlKey` elsewhere. Single binding string, no `meta+slash, ctrl+slash` comma-delimiter needed. The roadmap brief specified the comma-delimited form; this synthesis upgrades to `mod+slash` per brief-2's source-inspection.

### 3.4 `preventDefault: true` on the `mod+slash` hotkey

Brief-2 §7 AC7: without `preventDefault`, pressing Cmd+/ inside any focused input would also insert a `/` character. Set `preventDefault: true` explicitly.

### 3.5 Shortcut registry: Option 1 (flat const array)

Brief-2 §3.6: tiny shortcut count for m10 makes the React-context auto-registry (Option 3) overkill. Flat const with `as const` typing is the pragmatic choice. When the count grows (m11 cmdk, future Cmd+K command registry), revisit Option 3.

### 3.6 KeyboardHelpOverlay reuses the m7 Modal scaffold

The new overlay is a standard modal — wraps in `<Modal open={open} onClose={onClose} title="Keyboard shortcuts">` from `@/components/Modal`. Gets all m7 features for free: AnimatePresence scale-in + focus-trap + Escape-to-close + reduced-motion dual-guard + `inert`-on-exit (m7 rect H1). The KeyboardHelpOverlay component itself is just the modal CONTENT (the shortcut-list grid).

### 3.7 `isMacOS()` for OS-specific key labels

Brief-2 §3.5: `react-hotkeys-hook` exports `isMacOS()` from its index. Use it inside KeyboardHelpOverlay to render ⌘ on macOS and Ctrl on other platforms. Without this, users see the literal "mod+slash" string which is confusing.

### 3.8 Lazy-load KeyboardHelpOverlay via `React.lazy` + Suspense

Brief-1 §3.7: mirror the SettingsModal lazy-load pattern in App.tsx. The overlay loads only on first Cmd+/ press; `shortcuts.ts` (~0.5 KB) is the only new addition to the initial chunk besides react-hotkeys-hook itself.

### 3.9 `enableOnFormTags: true` on the ChatPanel hotkey

Brief-1 §3.9: the ChatPanel Escape handler fires while focus is in the chat textarea (ChatInput). Without `enableOnFormTags: true`, react-hotkeys-hook silently ignores keypresses when a form element is focused. Required for parity with the current `document.addEventListener` behavior.

### 3.10 `description` field on every `useHotkeys` call

Brief-2 §3.2 Options table: `description` is built into the hook's options for exactly this use case — a human-readable label that the help overlay can consume. Set `description` on each `useHotkeys` call to match the corresponding `label` in `shortcuts.ts`. Lightweight consistency check without the full Option 3 machinery.

### 3.11 Path decision: delegated

6 unique paths touched (package.json, package-lock.json, ChatPanel.tsx, shortcuts.ts, KeyboardHelpOverlay.tsx, KeyboardHelpOverlay.css, App.tsx). The slash command body's "≥ 6 files → delegated" canonical form applies. Dispatch ONE `milestone-implementer` Agent with `isolation: worktree`.

1. **`npm install react-hotkeys-hook`** — install at the latest 5.x range (`^5.3.2` per brief-2 §3.1). Build to confirm the deps tree is clean.

2. **Create `src/lib/shortcuts.ts`** with the typed const array. Seed entries: `mod+slash` (show help) + `escape` (close panel/modal). Future milestones append.

3. **Create `src/components/help/KeyboardHelpOverlay.tsx`** as a default-exported function component. Reuses `<Modal>` from `@/components/Modal`. Renders SHORTCUTS grouped by category in a two-column layout. Uses `isMacOS()` from `react-hotkeys-hook` to render key chips.

4. **Create `src/components/help/KeyboardHelpOverlay.css`** for the category-list layout (reuse modal-* classes where possible).

5. **Modify `src/components/chat/ChatPanel.tsx`** — replace the `useEffect` + `document.addEventListener("keydown", ...)` at lines 48-55 with `useHotkeys("escape", onClose, { enableOnFormTags: true, description: "Close chat panel" })`. Keep the JSX `onKeyDown={trapFocus}` at line 63 intact.

8. **Single commit** — `feat(deps): react-hotkeys-hook + Cmd+/ help overlay (m10)` (sample subject, 50 chars after prefix — verify length before commit).

The implementer must NOT migrate any JSX `onKeyDown=` handler to `useHotkeys`. The post-implementation grep `grep -rn 'addEventListener.*keydown' src/` must return empty.

## 6. Implementation acceptance criteria

1. `package.json` includes `react-hotkeys-hook@^5.3.2` (or latest 5.x compatible).
2. **Post-migration grep** `grep -rn 'addEventListener.*keydown' src/` returns empty.
3. **`ChatPanel.tsx`** uses `useHotkeys("escape", onClose, { enableOnFormTags: true, description: "Close chat panel" })`. The JSX `onKeyDown={trapFocus}` is preserved.
4. **No `Modal.tsx`** keyboard handling changed.
5. **`src/lib/shortcuts.ts`** exports `SHORTCUTS` (a `readonly` const array) and a `Shortcut` type. Minimum entries: `mod+slash` (Show keyboard shortcuts, App) + `escape` (Close panel / modal, App).
6. **`KeyboardHelpOverlay.tsx`** is lazy-loaded via `React.lazy()` in App.tsx. Renders via `<Modal>`. Uses `isMacOS()` for key chip labels. Categories rendered as grouped headers.
7. **App.tsx** `useHotkeys("mod+slash", () => setHelpOpen((open) => !open), { preventDefault: true, description: "Show keyboard shortcuts" })`.
8. **Build passes** (`npm run build`): zero TS strict errors. Initial chunk ≤ 260 kB.
9. **Manual smoke** in dev:
   - Press Cmd+/ (Mac) or Ctrl+/ (Win/Linux) → overlay opens with scale-in (m7 modal animation).
   - Overlay lists all SHORTCUTS grouped by category; key chips show ⌘ on Mac, Ctrl elsewhere.
   - Press Cmd+/ again → overlay closes (toggle behavior).
   - Press Escape → overlay closes.
   - Pressing Cmd+/ inside a focused input does NOT insert a `/` character (preventDefault works).
   - Open chat panel → Escape closes it (replacement for the migrated addEventListener).
   - Open Settings → Escape still closes it (Modal.tsx Escape untouched).
   - Open Settings → open nested ConfirmDialog → Escape closes only the ConfirmDialog (stopPropagation still works).

## 7. Riskiest assumption + alternative

**Risk:** Brief-2 §5 — the implementer may over-interpret the s17 "replace ad-hoc keydown listeners" wording and migrate Modal.tsx's JSX `onKeyDown` to `useHotkeys`, breaking modal-stack semantics. This synthesis explicitly forbids that migration (§3.2 + AC4), but the implementer agent's prompt must reinforce the boundary.

**Mitigation:** the dispatcher's prompt to the implementer must include the literal text "Modal.tsx Escape handling MUST stay JSX-bound. Do NOT call useHotkeys inside Modal.tsx." as a hard constraint.

**Alternative if `react-hotkeys-hook` lands in the deferred chunk via some Vite tree-shaking surprise:** the +3 kB cost moves out of the initial chunk. Probably wishful — Vite typically tree-shakes deps into whatever chunk first imports them. The ChatPanel and App.tsx both import from `react-hotkeys-hook`, so the dep will be hoisted to the chunk that contains both consumers (likely the initial chunk via App.tsx).

## 8. Open questions for the implementer (≤5)

1. **`shortcuts.ts` entry shape** — synthesis §3.5 prescribes a flat const array with `keys`, `label`, `category` fields. Confirm. Add a `description` field if more verbose tooltip text is desired; otherwise `label` alone is sufficient for the help overlay.
2. **Category names** — App, Navigation, Editing? Brief-2 §3.5 cites "Navigation / Editing / App" as the 2026 SOTA grouping. For m10 with 2 entries, only "App" applies. Future shortcuts (Cmd+K palette in m11, todo navigation, etc.) will add Navigation + Editing groups.
3. **Help overlay layout** — two-column grid (label | key chip) per category, or table format? Recommend grid; cleanest for short-label / short-key pairs.
4. **`description` on the registry vs `useHotkeys` option** — keep them in sync by setting both to the same string, OR have each `useHotkeys` call pass a `description` that the registry COPIES from. For m10, hand-sync is sufficient (2 entries).
5. **Caret pin policy** — brief-1 §4.5 asked: `^5.3.2` allows minor + patch auto-upgrades. The library has 85 releases — minor bumps are frequent. `^5.3.2` is the canonical npm pattern; sticking with caret is the standard choice and matches what proclivity does for lucide-react / motion. Confirm.
