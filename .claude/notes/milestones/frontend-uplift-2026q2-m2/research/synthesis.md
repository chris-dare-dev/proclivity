## 3. Recommended implementation pattern

In `src/newtab/App.tsx`:

```tsx
// near other top imports
import { LazyMotion } from "motion/react";

// loader fn outside the component so it's stable across renders
const loadDomAnimation = () =>
  import("motion/react").then((mod) => mod.domAnimation);

// in the App component, wrap the existing JSX root
return (
  <LazyMotion features={loadDomAnimation} strict>
    {/* existing app body unchanged */}
  </LazyMotion>
);
```

Key design choices (both briefs aligned):
- **`strict` prop** — enforces use of `m.*` over `motion.*`, which is what keeps the bundle small. Future consumers MUST use `m.div` not `motion.div`. With `strict`, the wrong form throws at dev time.
- **Deferred features loader** — `loadDomAnimation` returns a dynamic import; the heavy ~15 KB chunk loads after first paint. This is the canonical LazyMotion bundle-budget pattern from motion's docs.
- **No `m.*` consumers in this milestone** — m2 only lands the foundation. m4/m3/follow-ons add the actual motion usage. The implementer should NOT add demo motion components.

## 7. Riskiest assumption + alternative

**Risk:** The s5 absolute "≤ 200 kB" gate, taken literally, would force abort even with a zero-byte motion install (the baseline is already over). Treating s5 strictly would block the entire e1 epic and downstream value epics indefinitely. Both researchers independently confirm this.

**Mitigation chosen (per §1 / §6):** delta gate + hard 220 kB ceiling. The s5 wording is treated as a tightening overlay on the CLAUDE.md soft policy that doesn't apply because the baseline is already past the soft threshold.

**Alternative paths if the LazyMotion wrapper still pushes the chunk too high (brief-2 §4):**
- (a) Move `<LazyMotion>` inside `<Suspense>` so its sync footprint defers to the suspense fallback. Cost: changes the App.tsx render tree more invasively.
- (b) Skip `LazyMotion` entirely and import only `m` directly; rely on tree-shaking. Cost: forfeits the `strict` mode benefit and the lazy-load discipline.
- (c) Defer m2 entirely and run a chunk-budget-cleanup milestone first to recover headroom (e.g., split QuickPrompt / Calendar lazier).

Recommend (a) only if the m2 build pushes the chunk past ~215 kB. Recommend (c) only if (a) also fails.
